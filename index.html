Root CA Generator

Top-level root authority (Self-Signed). Required to sign subordinate certificates.

Main authority name displayed in the user's browser.
For a new Root CA, RSA 4096, ECDSA P-384 or Ed25519 is recommended today.
Root authority is usually issued for a very long period (10-20 years).

Intermediate CA Generator

Subordinate authority for day-to-day certificate issuance. Enhances security – Root CA can remain stored offline.

Select the parent authority that will sign this Intermediate CA.
Specifies how many subordinate CAs this authority can issue. Value "0" means it can only issue leaf certificates.

Leaf Certificate (End-Entity)

End-entity certificate for HTTPS websites, VPN servers, containers, IoT devices, or user identification.

Select a template to auto-populate the values below.
Comma-separated domains or IP addresses. Modern browsers require valid SAN, otherwise the certificate will be rejected.
The maximum validity for public HTTPS websites is currently 398 days.
Defines what purpose the operating system technically permits this certificate for. (Note: Key Usage attribute 'Key Encipherment' is only required and configured for RSA keys; for ECDSA/Ed25519 only Digital Signature applies).

Certificate Signing Request (CSR) Generator

Generate a new private key and corresponding signing request (PKCS#10 CSR) for an external CA or to test in the Sign CSR section.

Fully qualified domain name (FQDN) of the server or subject name.
All domains and IP addresses (comma-separated) for which the certificate should be valid.
Selects cryptographic algorithm used to generate key pair and sign the CSR request itself.

Output: Generated Files

Certificate Signing Request (CSR) Signing

Sign a certificate for a device when you do not (or must not) possess the private key. The device only provides a .csr file.

Attribute Review Before Signing

Extracted from request. You can add or remove domains that will actually be permitted for the certificate.

Cross-Signing

Cross-signing preserves the original authority key while establishing trust through another existing (e.g. older) Root CA. Frequently used for smooth migration to new keys without breaking trust on legacy devices.

Certificate & CSR Inspector

Quick inspection of any certificate or request. All decoding happens strictly locally in your browser; no data is transmitted.

Drag & drop .crt, .pem, or .csr file here or click to browse
